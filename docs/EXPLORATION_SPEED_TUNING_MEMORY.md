## 3. 证据等级和禁止混淆的事情

每个结论使用以下之一：

- **源码事实**：标明当前文件/逻辑，并能从当前 checkout 复核。
- **模型内观察**：有场景、参数、种子、测试二进制和原始轨迹。只对相应模型成立。
- **实机观察/拟合**：标明 bag、时间段和估计方法；不能扩大到未观测工况。
- **推测**：明确下一步如何验证。不得改写成“已找到根因”。
- **候选补丁**：说明只存在隔离副本，列出已测和未测。
- **生产已修改**：必须有真实 diff，列出全部旧值 → 新值。测试构建、生产源码修改、用户编译部署、实机验证是四件不同的事。

禁止：只报告最快 seed；删掉基线失败；把 `result.passed=true` 当精度合格；把采样前过冲忽略掉；用旧二进制验证新源码；把平均改善解释为所有场景改善；承诺“绝无 bug/绝不撞”。

## 5. 分层筛选流程

1. **核对基线**：当前源码、启用开关、坐标/单位、测试模型、工具是否真正调用当前算法。
2. **单因素和少量组合**：确认收益来自哪里；保留没有收益和变差的结果。
3. **常规多模型**：默认 delayed、漂移、1.5 倍滞后；记录分段用时，而非只看总时长。
4. **多 seed 和不同障碍布局**：在基线成功与基线失败两类中分别评估；不能把已知失败种子简单剔除。
5. **轨迹台架**：`--real`、`--real --lag 1.5`，检查最大跟线误差、来回修正、横向反复、角速度，不只看平均误差。
6. **近障压力**：稀疏/中断点云、位姿噪声、低速死区、迟滞、不同方向和幅度的推扰。
7. **两种推扰定位均要做**：相同绝对时间配对；以及各候选在相同任务阶段自己最贴障的位置配对。提速后可能已离开危险区，只有第一种会漏风险。
8. **实机响应敏感性**：用 bag 限定延迟/响应/稳态增益，同时保留更恶劣模型；不把一次直线拟合泛化到全飞行。
9. **精度复核**：3/3 投放，每次相对真实目标 ≤ 0.10 米，并检查采样入场惯性和释放等待期间漂移。旧 `release_windows_exact` 从 Send 起 1 秒，不能称完整物理 Wait；新验证须覆盖 Send 至实际 Wait 退出，参见下方口径纠正。
10. **最终交叉复核**：候选组合对应的真实源码快照重新构建，跑完整压力集，核对冻结模块不变，记录剩余盲点，再决定是否写生产。

20ms 主循环内不新增高代价搜索。能用参数可靠解决就不加逻辑；参数无法解决时，先定位控制机制，再试小补丁。

- `result.passed` 不包含全部投准条件，必须单独查每次释放误差。
- `campaign.py` 的释放误差来自 0.1s trace 插值，参照的是算法估计目标。视觉噪声测试须看 `response_engine` 的 50Hz 相变瞬时 `release_samples` 与真目标误差。
- `state.target_id` 是内部队列编号，不是场景视觉类别 ID。真实目标按估计目标坐标匹配场景目标，并保存匹配距离；目标过近/关联歧义时不能盲目用最近匹配。
- 3 次投放完成会提前归航，覆盖率不足 90%/95%不一定是覆盖算法失败。覆盖效率另用“无目标、仅覆盖”场景测达到 90%/95%的用时；旧记忆里“全任务必须90%”不可套用于当前三投即返航流程。
- 测试器没有真实飞控、起降动力学、三维地效/涡流和真实相机。模拟瞬移推扰仅是压力条件，不代表已经验证真实涡流。
- 当前投掷相对起飞雷达高度是 `0.03m`，不是提示词里的 `0.5m`。不要擅自改它。低空/地面余量必须区分相对起飞高度与离地高度，模型没有真实接地碰撞。
- 原始日志中 socket/硬件 I/O 被离线工具主动拦截是预期隔离行为，先看真实异常位置，不把它当网络连接故障。
- 独立 `tracker_bench` 首次 `at_goal` 即结束，不含惯性滑停或真实 Node 接管。必须报告入圈实速；台架通过不代表已经停稳。完整 Node 往往同拍结束观察、下一拍接新路径，不能自造持续旧 tracker 的尾段替代它。见 `cruise_agent_tracker_scope_correction.md`。
- 离线工具已把任务强制置为 EXPLORATION。若从首拍就延迟给主控第一条位姿，会把默认 Z=0 锁成巡航高度，造成假提速。保留这种启动反例，但正常飞行反馈延迟试验须先送足初始位姿；本轮用前2秒正常、随后排队延迟。见 `pose_delay_revision_history.json`、`safety_agent_pose_delay_report.md`。

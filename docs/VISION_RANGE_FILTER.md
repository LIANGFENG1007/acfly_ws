# 视觉坐标接收与探索共用可视距离

用户要求只接受 3m 内的视觉坐标，随后明确要求共用原探索可视距离，不新增参数。用户自行上传 NX；此次只改本机 `/home/yk/acfly_ws`，隔离副本构建，不编译部署正式工作区或 NX。

## 行为

探索节点从视觉共享内存读到新帧后，在远距确认、目标队列、线索回访、近距确认和投放采样之前，用当前有效飞机 XY 计算 `hypot(target.x-px, target.y-py)`，只保留 `≤fov_range` 的目标。该值就是覆盖栅格现有的 `gcfg_.fov_range`，没有独立视觉距离参数，也不额外改变角度判据。

- 恰好在可视距离上保留，超出即忽略；XY 为同一个 `camera_init` 世界坐标系。不是到原点的距离，也不含高度。
- 一帧含多个目标时分别过滤；全部超距后仍保留该新帧的序号/时间和空目标列表，打断未完成的连续确认，不复用上一帧。
- 没有有效、新鲜飞机定位时不接纳目标。被忽略的远处点不加入永久黑名单，之后飞机接近、再次看到时可以接收。
- 这是新观测的接收条件，不撤销此前在合法距离内确认的目标，也不改变已开始的投放阶段。视觉端仍可发送远处点，探索端会忽略它们。

## 调整入口

默认值在 `src/exploration_planner/include/exploration_planner/params.hpp` 的 `FOV_RANGE=3.0`。也可以沿用节点启动参数 `--ros-args -p fov_range:=2.5`。修改编译期默认值须重新构建；启动参数在节点启动时读取，未新增在线动态更新机制。覆盖范围与视觉坐标接收范围共用同一值。

诊断话题增加 `vision_accept_range_m` 与 `vision_range_dropped`。后者是本次节点进程累计因超距或位姿不可用而忽略的目标数（类别黑名单先执行）。

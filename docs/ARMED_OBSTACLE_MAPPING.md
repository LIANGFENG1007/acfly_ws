# 探索建图从首次解锁开始

用户在 2026-10-14 澄清：原先启动探索算法就开始建图，现在要检测到飞机解锁才开始。裁判可以在程序启动后、飞机解锁前移动障碍物。

## 行为

- 探索节点启动后，等待 `/mavros/state` 中 `connected && armed`，期间不累计探索障碍点云，也不累计覆盖栅格的已扫描区域。
- 首次收到上述状态时，记录节点 ROS 时间，从这时开始接纳探索点云。采集时间早于该时刻的排队点云不进入障碍地图；点云与节点须使用一致的 ROS 时间基准。
- 解锁后仍采用原先的多帧累计、聚类、平滑及障碍回收规则。不是解锁瞬间冻结地图，也不要求先进入 OFFBOARD。
- 同一次节点运行期间，重复状态、断连、上锁和再解锁不会清除地图或重设开始时间。启动时飞机已经解锁，首次收到有效已解锁状态即可开始。新一轮需要全新地图时重启探索节点。
- 走廊点云处理仍在原位置执行；主控、SLAM 和飞控接口逻辑未改。雷达原始点云或 SLAM 显示仍可能在解锁前更新，此改动控制的是探索障碍地图与覆盖记录。
- 直接驱动节点的离线工具也需要提供解锁状态才能验证建图；没有状态输入时地图保持未开启。此前提速结果对应其保存的旧源码快照，不能直接作为本次新源码的飞行用时证据。

新增只读状态订阅属于本次用户要求的实现范围，优先于已收尾的旧提速任务“不新增订阅”限制。未调整飞行参数。

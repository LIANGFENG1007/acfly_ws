## 背景

一台无人机会通过 **UDP 单播**持续向我这台机器上报遥测数据。我需要写一个接收程序把它显示/记录下来。

飞机端**只发不收**，不需要我这边做任何握手或回应。飞机不关心我在不在线——我没开机、掉线、重启，都不影响它飞行。

**为什么用 UDP 而不是 ROS 话题**：两台机器同一 ROS domain 时，Fast DDS 靠组播做发现且是"全连接"，飞机上 mavros 有 50+ 插件节点，一旦建立跨机 ROS 连接就会把 WiFi 组播挤爆、拖垮飞控串口的实时性。所以走裸 UDP。

## 网络参数

| 项目 | 值 |
|---|---|
| 我的 IP（接收端） | `192.168.12.187` |
| **UDP 端口** | **`9872`** |
| 方向 | 飞机 → 我（单向） |
| 上报频率 | 约 10 Hz |
| 飞机上其他端口（别混） | `9870` 小车位姿、`9871` 启动指令 |

## 协议格式（飞机端已固定，不能改）

**小端字节序，定长 64 字节，无填充**（发送端用 `#pragma pack(1)` + `static_assert` 锁死）：

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | uint32 | `magic` | `0x544C4D31`（ASCII `'TLM1'`）。**不等于这个值的包必须丢弃** |
| 4 | uint32 | `seq` | 序号，每包 +1。用来算丢包率 |
| 8 | double | `stamp` | 发送时刻，**飞机的** `CLOCK_MONOTONIC` 秒 |
| 16 | double | `drone_x` | 飞机坐标 X（飞机 SLAM 系，米） |
| 24 | double | `drone_y` | 飞机坐标 Y |
| 32 | double | `drone_z` | 飞机坐标 Z（高度） |
| 40 | double | `car_x` | **小车原始坐标 X**（见下方重要说明） |
| 48 | double | `car_y` | **小车原始坐标 Y** |
| 56 | int32 | `status` | 飞行状态，见下表 |
| 60 | int32 | `flags` | 位标志，见下方「flags 各位含义」 |

### `flags` 各位含义（★很重要，别忽略★）

| 位 | 值 | 含义 | 为 0 时说明什么 |
|---|---|---|---|
| bit0 | 1 | 小车数据新鲜 | `car_x/y` 是**最后已知位置**，不是当前位置（小车雷达断了） |
| bit1 | 2 | 视觉数据新鲜 | 视觉没看到目标 / 视觉程序挂了 |
| **bit2** | **4** | **飞机位姿有效** | ⚠️ **`drone_x/y/z` 全是 0 且无意义**（SLAM 没启动或挂了） |

**bit2 必须检查**：飞机无位姿时坐标字段会是 `(0,0,0)`。如果不看这个位，
你会把"SLAM 挂了"画成"飞机停在原点"——这两种情况的坐标数值完全一样，
只能靠 bit2 区分。建议 bit2=0 时在界面上把飞机坐标显示成灰色或标"无效"。

同理 bit0=0 时，`car_x/y` 是小车**最后一次**被看到的位置（不是 0，这样你能看出
它最后在哪、从哪断的），界面上应该标注成"已断开 N 秒"而不是当作实时位置。

### 飞行状态码 `status`

| 值 | 含义 |
|---|---|
| `1` | 起飞 |
| `2` | 追踪（跟着小车飞） |
| `3` | 投掷（视觉锁定 + 投放） |
| `4` | 降落（含投掷后返航） |
| `0` | 其它（开机检测、地面待机、任务已结束等） |

### ⚠️ `car_x` / `car_y` 是「原始坐标」，和飞机坐标**不在同一个坐标系**

小车有自己独立的一套 SLAM，这两个字段是**小车雷达直接报的原始值**，没有做任何坐标变换。

所以：
- **不能**直接把 `(car_x, car_y)` 和 `(drone_x, drone_y)` 画在同一张图上，它们原点不同
- 想画在一起，需要加上飞机端的标定偏移量：
  ```
  小车在飞机坐标系的位置 = (car_x + CAR_ORIGIN_X, car_y + CAR_ORIGIN_Y)
  ```
  这两个偏移量我会另外告诉你（在飞机的 `params.hpp` 里，会随场地重新标定而改变）

**为什么发原始值**：标定量填错时，换算后的坐标是错的，但原始值仍然正确——这样能分清"是标定错了"还是"小车雷达本身有问题"。

### ⚠️ `stamp` 不能用来算延迟

它是**飞机的** monotonic 时钟（从飞机开机起算），和我这台机器**不同源**，相减没有物理意义。

要判断数据新不新，用**我自己收包的时刻**：记录最后一次收到包的本机时间，超过比如 1 秒没新包就认为链路断了。

## 请你帮我做的事

### 任务 1：写一个接收程序

语言用 **Python** 就好（免编译、好改）。要求：

- 绑定 `0.0.0.0:9872` 接收
- 按上面的协议表解包。Python 格式字符串是 **`'<IIddddddii'`**（已验证 `struct.calcsize` = 64）：
  ```python
  magic, seq, stamp, dx, dy, dz, cx, cy, status, flags = struct.unpack('<IIddddddii', data)
  ```
  即：uint32×2 + double×6 + int32×2，共 10 个字段
- **丢弃**：长度 ≠ 64 的包、`magic` 不匹配的包
- 每收到一包，在**同一行原地刷新**显示（不要一直往下滚屏）：
  - 飞机坐标 (x, y, z)
  - 小车原始坐标 (x, y)
  - 飞行状态（**显示中文名**，不要只显示数字）
  - 实时频率（Hz）
  - 丢包统计（靠 `seq` 跳号算）
- **状态用不同颜色区分**（终端 ANSI 颜色即可），让我一眼看出现在在干什么
- **按 `flags` 标注数据可信度**：
  - bit2=0 → 飞机坐标显示成灰色或直接标"SLAM无效"（★别当真实坐标画★）
  - bit0=0 → 小车坐标标"已断开"（那是最后已知位置）
  - bit1=0 → 标"视觉未识别"
- 超过 1 秒没收到新包 → 显示**红色**"链路断开"提示，并显示已断开多久

### 任务 2：数据记录

- 列：本机接收时间、seq、飞机xyz、小车原始xy、status、flags
- 边收边写（不要缓存到退出才写，中途断电会丢）

### 任务 3：告诉我怎么验证

## 终端打印行为（按需求）

- **正常时完全静默**，一行都不打
- 启动时打一条 INFO 说明上报已启用（确认配置生效用）
- **发送失败才打红色 `RCLCPP_ERROR`**，且 5 秒节流，内容含连续失败次数、累计成功/失败数、目标地址

## 状态映射表

内部状态多，归并成需求要的四类：

| 遥测码 | 内部状态 |
|---|---|
| 1 起飞 | `TAKEOFF` / `WAIT_AFTER_TAKEOFF` / `HOVER_3S` / `TAKEOFF_AGAIN` / `REARM` |
| 2 追踪 | `TRACK_CAR` |
| 3 投掷 | `LOCK_DROP` |
| 4 降落 | `RETURN_HOME_DROP` / `GO_HOME` / `LAND` / `LAND_THEN_WAIT` |
| 0 其它 | 其余（`BOOT_CHECK`、走线类、`FINISHED` 等） |

加新状态时记得在 `telemetry_status()` 里归类——漏了会落到 `default`(0)，不报错但监控端看不出在干什么。

## 已验证（24 项测试全过）

- 包长 64 字节、magic、端口与 9870/9871 不冲突
- **真实往返**：飞机 xyz、小车原始 xy 精确一致到 1e-12；status/flags 正确
- `seq` 递增（监控端可算丢包）
- ★**目标不可达时不阻塞**★：最坏单次 `send()` = **0.076 ms**（一拍预算 20ms），
  这是最关键的一条——遥测绝不能拖慢 50Hz 控制循环
- 非法 IP 不崩溃，只是 `ok()=false` 并禁用上报
- 脏包（magic 错）可被接收端过滤

## 飞机端自测（不用等监控端写好）

```bash
# 终端1：假装监控端，看能不能收到
python3 -c "
import socket, struct
s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET,socket.SO_REUSEADDR,1)
s.bind(('0.0.0.0',9872))
print('监听 9872 …')
N={0:'其它',1:'起飞',2:'追踪',3:'投掷',4:'降落'}
while True:
    d,a=s.recvfrom(128)
    if len(d)!=64: continue
    m,seq,stamp,dx,dy,dz,cx,cy,status,flags=struct.unpack('<IIddddddii',d)
    if m!=0x544C4D31: continue
    print(f'seq={seq:<6} 飞机({dx:7.2f},{dy:7.2f},{dz:5.2f}) '
          f'小车原始({cx:7.2f},{cy:7.2f}) 状态={N.get(status,status)} flags={flags:#x}')
"

# 终端2：把 TLM_DEST_IP 临时改成 127.0.0.1 重编，或直接跑主控看终端1有没有输出
```

**注意**：要在飞机上自测，得把 `TLM_DEST_IP` 改成 `"127.0.0.1"` 重新编译；
或者在监控端跑上面的脚本（IP 已经是 192.168.12.187，直接就能收）。

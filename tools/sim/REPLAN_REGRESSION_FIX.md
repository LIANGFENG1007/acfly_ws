# 转身无解、换线跳动与小点回追修复

2026-09-09。对应用户报告：频繁转身无解、规划线来回跳动、小拐点引发左右旋转。
本次保持探索速度上限 0.60 m/s、控制前瞻 0.50 m、横向惯性预测 0.55 s。

## 修复的具体错误

- 剩余路线检查以前连回上一拍的投影点，还可能先横向连到当前路线垂足。
  在已经进入额外障碍余量、正向外退出时，这个并非实际前进方向的连接会被
  判为朝障碍内侧运动，导致安全路线反复失效。现在用同一受限进度投影检查当前
  位置，连接到下一前向参考；真正未通过的尖角仍保留，连接和后续段均完整验障。
- 替换非空轨迹时，旧的 aligning 状态没有重置。新路线已经对正，也会继承旧路线
  的刹停转向。现在重置路线相关的对齐状态，保留速度和角速度指令的连续限幅。
- 观察点已到达、仍在刹车时，稍微滑出终点容差就会重新追旧点，出现“剩余路程=0
  却回头转向”。现在锁定已到达状态，制动期间不再调用旧终点的跟踪转向，停稳
  后才释放旧观察点并重新规划。
- 转身探测原先使用刹车前的位置，或到达朝向后重新选择另一条探测路线。
  现在刹稳后从实际位置确认方向，保留仍安全的探测路径；失效时才更新。
- 失败后此前用 plan_pending 连续按控制频率换目标，并跳过整个条带。
  现在暂缓单个观察点，按正常规划周期重试；转向超时不再被说成“整片真被围死”。
- 平滑前合并短于 0.10 m、偏离替代直线不超过 0.02 m 的冗余引导点。
  只有替代段通过原障碍和场界检查才合并，真实绕障拐点和任务终点保留。
- 新探索引导路优先留出 0.08 m 的额外空间，减少规划贴着障碍判定边界的情况。
  若额外空间下无路，回退到原安全余量搜索；执行轨迹仍通过原完整安全校验。
  此项只用于探索搜索，不改变走廊点云处理或门宽判定。

参数均在 `src/exploration_planner/include/exploration_planner/params.hpp`：
`EXPLORE_GUIDE_MIN_SEGMENT_M=0.10`、`EXPLORE_GUIDE_MAX_DEVIATION_M=0.02`、
`EXPLORE_PLAN_RESERVE_M=0.08`、`TURN_SOLVE_RESEARCH_EVERY=10`。
最后一项在 50 Hz 控制下表示每 0.2 s 检查探测路径，转向控制仍逐拍执行。
用户原来的启动命令和随机障碍生成命令保持不变。

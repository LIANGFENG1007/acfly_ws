# 探索状态能否退出：第三轮检查

## 结论

不能保证“任何情况下都不会在空中一直等”。本轮修复了完成交接和后退重试中的逻辑缺陷，以及定位断流、后退方向检查中的问题。但目前没有全任务的无进展超时/失败结束策略；无路、无有效门洞、持续定位断流、必经点未收到放行等条件仍可无限等待。没有把等待超时直接等同于任务成功，也没有加入自动降落动作。

修改仅在本机 `/home/yk/acfly_ws`，未修改或部署 NX，未进行实飞。本轮没有实测 NX 的 CPU 和线程调度。

## 已修复

### 1. 已完成却等不到主控认可

旧主控先等 `/exploration/finished=false`，再允许 `true` 结束任务。该订阅使用 transient-local、keep-last 深度 1；忙时或晚加入只保留最新的 true，可能永远没有机会看到前一条 false。规划器只在状态切换时发布完成，主控则一直留在 EXPLORATION。

现在完成消息通过 `/exploration/finished_goal` 发布 `std_msgs/Header`，原样回传启动本次探索的 goal 的时间戳及 frame_id。主控验证任务标识，不再依赖 false→true 的消息边沿。上一任务的完成不能结束新任务，即使终点坐标相同。旧 Bool 话题仍用于显示/录制。

验证覆盖：规划器实际发布的完成消息匹配原始 goal；同坐标下一任务使用新标识；主控匹配逻辑能在没有前置 false 时接受当前完成，拒绝旧任务、错误坐标系和空标识。

**转到 NX 时必须同时更新并编译 `fly_mission` 与 `exploration_planner`。新主控需要新规划器的完成接口。**

### 2. 后退超时每拍从头重启

修改前测试复现：后退 2.1 秒且位置不变，第一次调用判超时返回；下一拍 `retreating_` 已清零，被认为尚未尝试过，重新开始后退。计时器不能阻止永久重试，也会使无效规划持续运行。

现在超过时间或距离限制，会保留“本位置后退已用尽”的状态，规划器继续选择其他观察点。只有位置移动至少 `max(0.10 m, goal_tol)`、采纳了新的有效探索路线，或收到新任务，才允许再次尝试。测试覆盖超时后连续 20 拍不重启，以及移动后恢复尝试。

后退方向还补查整个计划后退段的障碍与边界。修改前测试复现：远离最近障碍的方向可能正对另一个障碍，仍会输出后退速度。现在退路不安全时停止，本轮超时规则仍有效。

### 3. 普通探索/归航沿用过期定位

旧节点只在通道移动分支检查定位新鲜度，普通探索、临时目标、归航主要检查 `has_pose_`。即使定位已停止，仍可能沿旧位姿控制并更新覆盖。

修改前测试复现过期定位仍产生运动或新覆盖。现在普通任务共用已有里程计超时参数（默认 0.30 秒），停止运动和覆盖更新；有效定位回来后恢复原任务。通道继续使用原有数据过期处理及诊断。该保护增加的是有原因、可恢复的停止，不是假装数据断流后还能可靠控制位置。

### 4. 空候选状态可诊断

未找到新观察点时增加 `no_observation_candidate` 原因与节流日志，说明当前覆盖率，以及正在续用旧安全路线还是等待可用路线。保持周期重试，不把“没有候选点”误报为完成。

## 已检查但仍属于等待策略的情况

| 条件 | 当前行为 | 是否有总等待上限 |
| --- | --- | --- |
| 视觉进入近距但一直无新识别帧 | 8 秒后暂缓目标、不计完成，释放给其他目标/探索 | 有近距确认超时；本轮断帧回归通过 |
| 临时目标首次进入 10 cm 后悬停 | 按原规则累计 3 秒；偏移纠正，不重置时间 | 有，按此前用户要求 |
| 当前场景没有安全观察点/终点路线 | 周期重试，有原因日志 | 无 |
| 通道墙/门/有效点云证据不足 | 等待有效数据；可行且有新鲜测量时定点纠偏 | 无 |
| 门前一直不能满足对中条件 | 纠偏、限制向前穿门 | 无；当前中心容差仅 0.015 m，另检查 0.40 秒预测横漂 |
| 里程计持续断流 | 停止水平/转向命令，主控按现有方式保高 | 无 |
| 规划进程停发命令 | 主控命令超时停止转发，控制器 watchdog 停止水平/yaw | 无自动结束/降落策略 |
| POI 等待外部放行 | 保持位置，等待对应坐标的放行消息 | 无 |

因此剩余的长期悬停需要根据日志中的等待原因判断，不能单凭显示速度 0.00 判断程序死锁。软件指令非零也不等于飞控一定能达到位置或航向阈值。

## 验证

本轮新加的回归直接调用实际节点控制链并截获发布消息，不连接飞控，不启动飞行。已分别在修改前复现后退超时重启、定位过期继续运动/覆盖、后退撞向第二障碍。完成通知的消息丢边沿风险由接口及状态逻辑审查确认；测试验证新的发送和接收判定。

最终结果：

- 规划器功能测试 **26/26 通过**，总耗时 68.91 秒；其中节点测试包含本轮新增的任务完成身份、定位断流/恢复、后退超时/恢复、退路第二障碍、视觉无新帧超时场景。
- 主控 `velocity_output_test` **1/1 通过**，涵盖完成身份匹配和已有最终 MAVROS 输出/恢复保护。
- `git diff --check` 通过。

此前已有格式/schema 检查失败没有计入功能测试通过统计。本轮没有重跑跨进程 ROS 通道脚本或进行实飞。

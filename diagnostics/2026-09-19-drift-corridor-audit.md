## 已确认的执行分支

| 分支 | 原来的问题 | 当前处理 |
| --- | --- | --- |
| 探索终点后的通道转向 | 水平速度超过 0.04 m/s 就同时清零 XY 和 yaw | 锁定转向开始的实际 XY，位置/速度反馈纠偏，同时继续转 yaw |
| 通道移动时修正大航向误差 | 漂移时先输出零速度等待刹停 | 在固定 XY 处修正航向，水平漂移不暂停 yaw |
| 探索原地找方向、观察点转向 | 依赖低水平速度；观察方向有新收益时可能中断转向 | 固定位置纠偏，已开始的转向继续到目标航向；仍检查角速度和实际障碍 |
| 路径大角度对准 | 原地转向只有 yaw，无主动 XY 纠偏 | 巡航保持原方式，原地转向允许有界前后/横向速度 |
| 尖角与滑过拐点 | 达不到低速阈值便不能换出段或请求重规划 | 按位置及路径进度开始定点转向；滑过拐点立即请求重新校验的路径 |
| 观察点/反向路径交接 | 依赖“先停稳” | 先到达当前有效段，再交接；漂移本身不永久阻塞下一段 |
| 归航、插点终点 | 进入位置容差后 tracker 输出零；漂出后可能转头追点 | 锁定终点和到达时航向，持续 XY 修正，不因漂移改追点方位 |
| 终点距离限速 | 合速度阻尼可能把转向 XY 修正也压成零 | 原地修正不经过巡航距离限速；巡航阻尼采用朝命令方向的速度分量 |
| 速度投影受阻 | 清零后等待速度降低才重规划，漂移会一直阻塞 | 有安全空间时输出有界、逐步增加的反向制动；持续受阻按时间重规划 |
| 边界处原地修正 | 短控制步被要求一次抵达完整安全边距 | 允许分多步向内恢复，禁止向外加深边界偏离，保留障碍碰撞检查 |
| 等待墙/门证据 | 有有效定位时仍只输出零速 | 有新鲜测量时锁定首次等待位置并纠偏；数据过期仍停止 |
| H 点结束 | 只给零速并等待水平速度阈值 | 修正 H 点位置，按位置和航向确认后结束 |

主控 `fly_mission` 普通 `TURN_YAW` 已经在动作开始时锁定 XY/Z，并同时输出 XY/Z 速度和 yaw rate；该路径没有水平停稳门槛。

保留的零输出包括：定位/有效点云过期、无有效路线、目标被占据、纠偏方向碰撞或不允许的越界。`GOAL_STOP_V` 只参与速度安全投影的噪声过滤，不再决定终点交接。旧 `CORRIDOR_STOP_SPEED`、`CARLIKE_ALIGN_STOP_SPEED` 参数为配置兼容保留。旧 `pd_core/pd_to_point` 在当前任务执行链没有调用者。

## 第二轮检查：最终输出与速度控制接口

沿 `exploration_planner → /exploration/cmd_vel → fly_mission → /mavros/setpoint_raw/local` 再次检查，新增以下修复。

1. **删除探索位置控制接口**：移除 `USE_POSITION_CONTROL`、`use_position_control`、`/exploration/target_pose` 发布/订阅、`EXTERNAL_POS` 模式及其状态和方法。探索、临时目标、归航和通道均通过速度输出。普通任务的起飞位置模式保留。原地纠偏仍使用位置误差算出有界 XY 速度，不向飞控发探索位置目标。旧位置模式锁存并抢占新鲜速度的分支随之消失。
2. **无效定位导致长期全零**：原主控直接把 NaN 高度写入位置差分/低通状态；后续有效帧也无法消除 NaN，最终 setpoint 的非有限数保护持续清零 XY/Z/yaw。测试已在修改前复现。现在进入滤波前验证位置和四元数，丢弃坏帧并重置差分状态；下一有效帧可恢复。保留最终输出的非有限数保护。
3. **普通探索路线结束后没有释放**：没有单独观察动作、终点也未投影的路线，在 tracker 到达后仍保留旧轨迹，可继续输出零而不切换。测试已在修改前复现。现在到达后清除执行路线、释放已选目标，下一拍重新选点。
4. **视觉分支再次放大已校验的纠偏**：外层曾把小速度强行提高到 0.12/0.16 m/s，并单独缩放横向分量，破坏转向保持/制动限幅。最终 `/exploration/cmd_vel` 回归测试在修改前失败。现在只允许按原方向降低速度上限，保持已校验的纠偏方向和加速度上限。转向/定点修正还要单独检查自身方向，不能因为视觉主路径有效就跳过这项避障。
5. **日志精度**：主控探索命令日志从 2 位改成 4 位小数。实际 0.002 m/s 以前会显示成 0.00；这是显示舍入，测试确认它没有在 MAVROS 消息中被舍入成零。该日志仍表示收到的命令，不冒充最终 setpoint 记录。

以上是源码/回归测试确认的缺陷；没有证据证明这三类新增缺陷均发生在此前那次实飞中。

### 仍可能为零的分支

- 没有有效初始位姿、没有可执行路线，或目标被障碍占据/越过允许边界。
- 转向或制动修正方向存在碰撞风险；安全检查不会为了保持非零而跳过。
- 通道缺少当前任务的入口/H 路线，或者平移阶段有效里程计/点云超时。初始原地转向可以在有效定位下继续，但过门需要有效点云。
- 门墙证据尚不够时不前进；有新鲜测量且修正可行时仍定点纠偏。中心线/预测横向位置未对齐也可能阻止向前穿门；当前位置 `CORRIDOR_CENTER_TOL=0.015 m`、预测时间 `0.40 s`，横漂会影响此条件。这属于穿门几何保护，没有放宽。
- 任务完成、路线切换的一拍，或刚好无需位置/速度/航向修正时，零指令可以是正常结果。
- 主控收到的速度超过 `EXPLORE_CMD_TIMEOUT_S=0.5 s` 不更新时停止转发，控制器最后一次收到转发命令后再超过 `0.3 s` 则水平/yaw 清零、继续保高。CPU 卡顿若造成这样的命令间断仍会触发保护；本次没有新增 NX 实测证明正在发生 CPU 断流。
